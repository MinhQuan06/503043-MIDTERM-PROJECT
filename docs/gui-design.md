# GUI architecture

The GUI uses separate screen and service classes so that menu navigation, search, playback, and drawing have distinct responsibilities.

## Screen flow

`MainMenu` offers Single Agent and Two Agents. Single Agent lets the user choose UCS or A*, calls the solver, then opens solution playback. Two Agents currently opens a separate placeholder screen; competitive rules and agent controllers are not implemented yet.

## Responsibilities

- `gui/app.py` defines `SokobanApp`, starts the menu, and routes the selected mode.
- `gui/screens/menu.py` renders the main menu and collects the mode and algorithm choice.
- `gui/screens/single_screen.py` loads the selected map and runs the search algorithm.
- `gui/screens/solution_screen.py` owns the solution playback window and controls.
- `gui/playback.py` stores the states generated by the action sequence and tracks the current step.
- `gui/renderer.py` draws the board and loads the sprites from `gui/assets/`.
- `core/problem.py` owns the immutable problem configuration and state transition rules; GUI code does not duplicate game rules.

## Playback controls

- Space toggles playback.
- Right arrow advances one action.
- Left arrow moves back one action.
- Escape closes playback and returns to the menu.
